# RoomFinder

מערכת שעוקבת אחרי אתרי דירות ושולחת התראה בטלגרם ברגע שמתפרסמת דירה חדשה שמתאימה לחיפוש.
לכל משתמש יש חיפוש משלו (ברירת המחדל: 4 חדרים להשכרה בראשון לציון), שמשנים בדשבורד.

## מה יש פה

| אתר | איך נבדק | כל כמה זמן (ברירת מחדל) |
|---|---|---|
| יד2 | דף החיפוש + ה-API שהאתר עצמו משתמש בו, כל העמודים | 10 דקות (בלילה 30) |
| מדלן | דף החיפוש + ה-API שהאתר עצמו משתמש בו, כל העמודים | 60 דקות (בלילה 120) |
| קומו | העמוד הראשון של התוצאות, ואם יש יותר מעמוד - מפוצל לטווחי מחיר (העמודים הבאים דורשים התחברות) | 30 דקות |
| הומלס | טבלת המודעות של העיר, מסוננת לפי חדרים ומחיר, כל העמודים | 30 דקות |
| OnMap | ה-API של החיפוש (כל המודעות בבקשה אחת) | 30 דקות |

כל האתרים נבדקים דרך Google Chrome שרץ בתוך הקונטיינר, מהרשת הביתית. יד2 ומדלן חוסמים שרתי ענן ובקשות שלא מגיעות מדפדפן אמיתי, ולכן המערכת צריכה לרוץ על מחשב בבית, והיא בודקת רק כשהוא דלוק.

- **מודעה חדשה** שמתאימה לחיפוש מגיעה לטלגרם עם תמונה, פרטים וכפתורים: ⭐ שמור, 🙈 לא רלוונטי, ו-📷 עוד תמונות (שאר התמונות של המודעה, כאלבום בתגובה להודעה).
- **ירידת מחיר** במודעה מתאימה נשלחת כהתראה 📉.
- **אותה דירה בכמה אתרים** מזוהה (לפי רחוב, מספר, חדרים ומחיר), ונשלחת עליה רק התראה אחת.
- **חיפוש לכל משתמש, בדיקה אחת לכולם:**
  - כל משתמש מגדיר לעצמו מה הוא מחפש (חדרים, מחיר, שכונות, ריהוט וכו'), ומקבל התראות רק על מה שמתאים לו.
  - האתרים לא נבדקים פעם לכל משתמש. החיפושים של כל המשתמשים הפעילים מאוחדים לחיפוש אחד לכל עיר, שמכסה את כולם: משתמש שמחפש 4-5 חדרים ומשתמש שמחפש 5-5.5 חדרים נבדקים יחד כ-4-5.5 חדרים, ומחיר בלי תקרה אצל אחד מבטל את התקרה. כל מודעה נשמרת פעם אחת, ונבדקת מול החיפוש של כל משתמש.
  - גם טווחים שלא נוגעים זה בזה (2 חדרים ו-6 חדרים) נבדקים כחיפוש אחד רחב: עוד כמה תוצאות עולות פחות מעוד טעינת דף, ושתי טעינות סמוכות הן מה שמפעיל את חסימת הבוטים (ראו [הערה על מדלן](#הערה-על-מדלן)).
  - רק מה שהאתרים עצמם מסננים לפיו (עיר, חדרים, מחיר, סוגי נכס, "ללא תיווך") מאוחד. שכונות, ריהוט, חניה, מ"ר ומילים שפוסלות הם של כל משתמש לעצמו.
  - את החיפוש המשולב רואים מנהלים בדף **מקורות**.
- **הבדיקה הראשונה** של כל אתר היא "ריצת בסיס": כל המודעות שכבר קיימות נשמרות בשקט, ומגיעה הודעת סיכום אחת.
  - כשמשתמש מרחיב את החיפוש המשולב (למשל מוסיף 5 חדרים), רק מודעות שהחיפוש הקודם לא היה מגיע אליהן נשמרות בשקט, ורק מי שהן מתאימות לו מקבל עליהן הודעת סיכום. מודעה חדשה בטווח שכבר נבדק מגיעה כרגיל, כך ששינוי של משתמש אחד לא משתיק את ההתראות של האחרים.
- **אתר שנכשל 3 פעמים ברצף** (למשל בגלל קפצ'ה) שולח התראה, ואחר כך הודעה נוספת כשהוא חוזר לעבוד.
- **טקסט המודעה, ריהוט וחניה:**
  - לכל מודעה חדשה המערכת קוראת את טקסט המודעה עוד לפני ההתראה, ושולפת ממנו, או משדות באתר, אם הדירה מרוהטת (כולל "חלקית") ואם יש חניה וכמה.
    - ביד2, בקומו ובהומלס מדף המודעה, שבו יש גם שדות של ריהוט וחניה.
    - ב-OnMap מה-API של האתר. חניה יש גם בתוצאות החיפוש.
    - במדלן הטקסט מגיע עם תוצאות החיפוש עצמן, כך שהוא ידוע לכל מודעה כבר מהבדיקה הראשונה, בלי לטעון עוד דף (ראו [הערה על מדלן](#הערה-על-מדלן)).
    - כשאין שדה של ריהוט או חניה, הם נקראים מהטקסט: "ללא ריהוט", "חניה בטאבו" וכדומה.
  - ביד2, בקומו, בהומלס וב-OnMap, מודעות קיימות מושלמות בהדרגה, עד 4 בכל בדיקה.
  - בהגדרות כל משתמש יכול לבחור "מרוהטת בלבד", "לא מרוהטת בלבד" או "רק עם חניה". מודעה שעוד לא ידוע עליה לא נפסלת.
- **חיפוש חופשי** בדף המודעות, בטקסט המודעה, בכותרת ובכתובת:
  - כל המילים צריכות להופיע, גם כחלק ממילה: "מרפסת" מוצא גם "ומרפסת" ו"המרפסת".
  - `"מרפסת שמש"` במירכאות מוצא את המילים ביחד, ו-`-שותפים` מוציא מודעות שהמילה מופיעה בהן.
  - יו"ד או וי"ו כפולות נחשבות כאחת, כך ש"חניה" מוצא גם "חנייה". כתיב חסר ומלא שונים יותר ("שרותים" / "שירותים") לא מאוחדים.
  - המילים שנמצאו מסומנות בכרטיס, ותיאור המודעה נפתח מעצמו כשהן בו. המספרים בלשוניות מתעדכנים לפי החיפוש.
  - מודעה שהטקסט שלה עוד לא נקרא נבדקת רק לפי הכותרת והכתובת, ומעל התוצאות כתוב כמה מודעות כאלה יש.
- **שכונות:**
  - בדף **שכונות** כל משתמש בוחר על המפה את השכונות שבהן הוא מחפש: לחיצה על שכונה, או ציור מסביב לכמה שכונות. מודעה משכונה אחרת לא נחשבת מתאימה לו ולא נשלחת לו עליה התראה.
  - כל מודעה משויכת לאחת מ-40 השכונות הרשמיות של ראשון לציון:
    - ביד2, במדלן וב-OnMap לפי הנקודה של המודעה על המפה.
    - בקומו ובהומלס לפי שם השכונה שבמודעה, גם כשהוא כתוב אחרת ("רמבם", "קרית", "נוה").
  - שם כללי מדי ("מרכז", "המזרח") לא משויך לשום שכונה, וגם מודעה בלי שכונה ובלי נקודה. מודעות כאלה עוברות את הסינון, אלא אם מכבים את זה בדף השכונות.
  - בכרטיס המודעה ובטלגרם מופיע "(לפי המפה: ...)" כשהשכונה לפי המפה שונה ממה שכתוב במודעה.
  - גבולות השכונות לקוחים ממערכת ה-GIS של עיריית ראשון לציון (שכבת "גבול שכונה"), והמפה מ-OpenStreetMap.

## התקנה

צריך רק [Docker Desktop](https://www.docker.com/products/docker-desktop/). Python, Chrome וכל השאר נמצאים בתוך הקונטיינר.

1. יוצרים בוט טלגרם: בטלגרם פותחים את ‎@BotFather ושולחים `/newbot`.
   - מומלץ גם לשלוח `/setjoingroups`, לבחור את הבוט ולבחור **Disable**, כדי שאף אחד לא יוכל להוסיף אותו לקבוצה.
2. מעתיקים את `.env.example` לקובץ `.env`, ומדביקים את ה-token בשורה `TELEGRAM_BOT_TOKEN=`. הקובץ `.env` לא נכנס ל-git.
3. מפעילים:
   ```powershell
   docker compose up -d --build
   ```
4. יוצרים את המשתמש הראשון (מנהל). הפקודה מדפיסה קישור הרשמה חד-פעמי; פותחים אותו ובוחרים שם משתמש וסיסמה:
   ```powershell
   docker compose exec app python -m roomfinder invite --admin
   ```
5. בדשבורד (http://localhost:8000), בדף **החשבון שלי**, לוחצים **➕ חבר טלגרם**, פותחים את הקישור (או סורקים את הקוד) ולוחצים Start בטלגרם.

## משתמשים והרשאות

- **בלי התחברות לא רואים כלום ולא עושים כלום.** כל כתובת בדשבורד, כולל כתובות שלא קיימות, מפנה לדף הכניסה. פתוחים רק דפי הכניסה, ההרשמה והאיפוס, וקובצי העיצוב.
- **אין הרשמה פתוחה.** חשבון נפתח רק מקישור הזמנה שמנהל יוצר בדף **משתמשים**. כל קישור חד-פעמי ותקף ל-3 ימים, ואפשר לבטל אותו לפני שנוצל.
- **תפקידים:**
  - מנהל: הכול, כולל ניהול משתמשים, המקורות (בדיקה ידנית, כיבוי, תדירות וכתובת מותאמת), שעות הלילה והדפדפן של המערכת.
  - משתמש: המודעות, החיפוש, ההתראות והטלגרם שלו. את המקורות הוא רואה, בלי לשנות אותם.
  - לכל משתמש יש חיפוש, שכונות, שעות שקטות, השהיית התראות והתראות על ירידות מחיר משלו.
  - גם הסימונים (חדשה, מועדפים, יצרתי קשר, "לא רלוונטי") וההערות הם של כל משתמש לעצמו, בדשבורד ובכפתורים בטלגרם.
  - התראות על אתר שנכשל, ועל אתר שחזר לעבוד, נשלחות רק למנהלים.
  - משתמש חדש מתחיל מחיפוש ברירת המחדל.
- **שכחת סיסמה?** מנהל יוצר קישור לאיפוס מדף המשתמשים. תקף ל-24 שעות ולשימוש אחד.
- **אם שכחת את הסיסמה של המנהל היחיד:**
  ```powershell
  docker compose exec app python -m roomfinder reset-link <username>
  ```
- **ניתוק והשבתה:** משתמש שמושבת או נמחק מתנתק מיד מכל המכשירים ומפסיק לקבל התראות בטלגרם. מדף **החשבון שלי** אפשר לנתק את כל המכשירים האחרים.
- **טלגרם:** הבוט עונה רק למי שחיבר טלגרם לחשבון פעיל, דרך קישור חד-פעמי (תקף ל-10 דקות) מדף החשבון. כל אחד אחר לא מקבל ממנו שום תשובה. כל צ'אט פועל בשם החשבון שחיבר אותו.
- **מה עוד מוגן:**
  - סיסמאות נשמרות רק כ-hash מסוג Argon2.
  - עוגיית ההתחברות מסומנת HttpOnly ו-SameSite.
  - אחרי 5 ניסיונות כושלים הכניסה ננעלת ל-15 דקות.
  - בקשות מאתרים אחרים נחסמות.
  - אין דף תיעוד API פתוח.
  - `/health` עונה רק מתוך הקונטיינר.
  - בייצוא ה-CSV, נוסחאות שמגיעות מטקסט של מודעות מנוטרלות.

רשימת המשתמשים משורת הפקודה: `docker compose exec app python -m roomfinder users`.

כדי שהמעקב ירוץ תמיד, מומלץ להפעיל ב-Docker Desktop את **Start Docker Desktop when you sign in**, ולוודא שהמחשב לא נכנס למצב שינה. הקונטיינר עולה מחדש מעצמו (`restart: unless-stopped`).

**להרצה קבועה על מחשב אחר בבית**, עם גישה מהטלפון מכל מקום, יש מדריך מלא: [HOSTING.md](HOSTING.md).

## שימוש יומיומי

- **דשבורד** (http://localhost:8000):
  - **מודעות:** חדשות / הכול / מועדפים / יצרתי קשר / לא רלוונטי / הוסרו, לפי החיפוש והסימונים שלך, עם חיפוש חופשי, סינון לפי אתר, שכונה (לפי המפה), מחיר, ריהוט וחניה, והערות אישיות לכל דירה.
    - בכל כרטיס אפשר לדפדף בין התמונות של המודעה: בהחלקה בטלפון, או בחיצים במחשב.
    - **🗺 מפה:** אותן מודעות, עם אותם לשונית וסינונים, כמחירים על המפה. לחיצה על מחיר מציגה את פרטי המודעה. מודעה בלי נקודה על המפה (קומו, הומלס) מוצגת באמצע השכונה שלה, במסגרת מקווקוות.
  - **מקורות:** המצב של כל אתר וכמה מודעות בו מתאימות לך. למנהלים גם: בדיקה ידנית ("בדוק עכשיו"), כיבוי והדלקה, תדירות, כתובת חיפוש מותאמת (במקום החיפוש המשולב), והחיפוש המשולב שהאתרים נבדקים בו.
    - ליד כל אתר יש קישור לחיפוש שלך באתר עצמו, עם הסינונים מההגדרות שלך (עיר, חדרים, מחיר, וסוגי נכס באתרים שיש בהם סינון כזה), וכפתור להעתקת הקישור. אם הוגדרה כתובת מותאמת, הקישור הוא אליה.
  - **שכונות:** בחירת השכונות על מפה, עם מספר המודעות המתאימות בכל שכונה.
  - **הגדרות:** מה אני מחפש, ההתראות שלי (השהיה, ירידות מחיר, ושעות שקטות שבהן ההודעות מגיעות בלי צליל), וייצוא ל-CSV עם הסימונים שלי. למנהלים גם שעות לילה (בדיקות פחות תכופות, לכולם).
  - **החשבון שלי:** טלגרם, החלפת סיסמה וניתוק מכשירים.
  - כשהדשבורד פתוח, מודעה חדשה מקפיצה גם התראת דפדפן עם צליל.
- **פקודות בטלגרם:** `/status`, `/latest` (האחרונות שמתאימות לך), `/pause` ו-`/resume` (ההתראות שלך בלבד).
- **הדפדפן של המערכת** (למנהלים, בדף **מקורות**): אם אתר מציג בדיקת "אני לא רובוט", אפשר לפתוח את הדפדפן בתוך הדשבורד, לפתור אותה בעצמך, ואז ללחוץ "בדוק עכשיו". אין לו פורט נפרד, והוא זמין רק אחרי כניסה כמנהל.

### הערה על מדלן
מדלן מוגן במערכת PerimeterX, שחוסמת דפדפנים שנראים לה אוטומטיים ומציגה בדיקת "לחץ והחזק", למשל כשנטען עוד דף זמן קצר אחרי הראשון. לכן דף החיפוש נטען רק פעם אחת בכל בדיקה, והעמודים הבאים נקראים מתוכו דרך ה-API של האתר, והוא נבדק רק פעם בשעה. טקסט המודעה מגיע עם תוצאות החיפוש, ודפי המודעות עצמם לא נפתחים אף פעם. אם הוא נחסם שוב ושוב, אפשר לפתור את הבדיקה ידנית בדפדפן של המערכת, או לכבות אותו בדף המקורות. רוב המודעות שבו מופיעות גם ביד2.

## תחזוקה

```powershell
docker compose logs -f app            # לוגים
docker compose restart app            # הפעלה מחדש
docker compose up -d --build          # אחרי עדכון קוד
```

הנתונים נשמרים ב-volume בשם `roomfinder_roomfinder-data`: מסד הנתונים (מודעות, סימונים, הערות, הגדרות, משתמשים וחיבורי טלגרם) ופרופיל הדפדפן. הם נשארים גם כשהקונטיינר נבנה מחדש, ב-`docker compose down` וב-`up -d --build`.

`docker compose down -v` **מוחק את ה-volume**, ואחריו המערכת מתחילה מאפס:
- כל המשתמשים נמחקים. יוצרים מנהל חדש עם `invite --admin`, כמו בהתקנה.
- צריך לחבר מחדש את הטלגרם מדף החשבון. ה-token נשאר, כי הוא ב-`.env`.
- כל משתמש צריך להגדיר מחדש את החיפוש וההעדפות שלו.
- הבדיקה הראשונה של כל אתר תהיה שוב ריצת בסיס.

גיבוי ושחזור (מתיקיית הפרויקט):
```powershell
# גיבוי לקובץ roomfinder-backup.tgz (עוצרים לרגע, כדי שמסד הנתונים לא ישתנה באמצע)
docker compose stop
docker run --rm -v roomfinder_roomfinder-data:/data -v ${PWD}:/backup alpine tar czf /backup/roomfinder-backup.tgz /data
docker compose start
# שחזור: קודם docker compose down, אחר כך
docker run --rm -v roomfinder_roomfinder-data:/data -v ${PWD}:/backup alpine sh -c "rm -rf /data/* && tar xzf /backup/roomfinder-backup.tgz -C /"
docker compose up -d
```

## פיתוח

הכול רץ בתוך Docker:

```powershell
# הרצה עם הקוד מהתיקייה וטעינה מחדש אוטומטית (בלי מתזמן)
docker compose -f compose.yaml -f compose.dev.yaml up -d --build

# בדיקות ו-lint
docker compose exec app pytest
docker compose exec app ruff check .

# בדיקה ידנית של אתר: רק מדפיס, בלי לשמור ובלי לשלוח
docker compose exec app python -m roomfinder fetch yad2
# בדיקה מלאה של אתר: שמירה והתראות
docker compose exec app python -m roomfinder run yad2
# הודעת בדיקה לטלגרם
docker compose exec app python -m roomfinder notify-test
```

מבנה עיקרי:
- `src/roomfinder/sources/`: מקור לכל אתר. כל מקור מחזיר רשימת `ListingData`.
- `searchers.py`: החיפוש של כל משתמש, איחוד החיפושים לחיפוש אחד לכל עיר, ומה כבר היה בטווח של הבדיקה הקודמת.
- `pipeline.py`: שמירה, ההתאמה לכל משתמש (`ListingMark`), זיהוי חדשות, ירידות מחיר ומודעות שהוסרו.
- `dedupe.py`: זיהוי אותה דירה בכמה אתרים.
- `areas.py` ו-`data/areas/`: מפת השכונות, ושיוך מודעה לשכונה (לפי נקודה או לפי שם).
- `runner.py`: בדיקה אחת של מקור, כולל התראות וטיפול בכשלונות.
- `scheduler.py`: תזמון עם השהיה אקראית, מצב לילה ו-backoff.
- `notify/telegram.py`: הבוט.
- `auth.py`: חשבונות, סיסמאות, התחברויות וקישורים חד-פעמיים.
- `web/`: הדשבורד (FastAPI, Jinja2, HTMX, Bootstrap RTL):
  - `security.py` ו-`main.py`: שער ההתחברות.
  - `accounts.py`: כניסה, הרשמה וניהול משתמשים.
  - `novnc.py`: הדפדפן של המערכת למנהלים.
  - `static/areas.js`: המפה של דף השכונות (Leaflet).
