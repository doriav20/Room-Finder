# RoomFinder

מערכת שעוקבת אחרי אתרי דירות ושולחת התראה בטלגרם ברגע שמתפרסמת דירה חדשה שמתאימה לחיפוש.
ברירת המחדל: 4 חדרים להשכרה בראשון לציון. אפשר לשנות את החיפוש בדשבורד.

## מה יש פה

| אתר | איך נבדק | כל כמה זמן (ברירת מחדל) |
|---|---|---|
| יד2 | דף החיפוש + ה-API שהאתר עצמו משתמש בו | 10 דקות (בלילה 30) |
| מדלן | הנתונים שמוטמעים בדף החיפוש | 60 דקות (בלילה 120) |
| קומו | דפי התוצאות | 30 דקות |
| הומלס | טבלת המודעות של העיר | 30 דקות |
| OnMap | ה-API של החיפוש | 30 דקות |

כל האתרים נבדקים דרך Google Chrome שרץ בתוך הקונטיינר, מהרשת הביתית. יד2 ומדלן חוסמים שרתי ענן ובקשות שלא מגיעות מדפדפן אמיתי, ולכן המערכת צריכה לרוץ על מחשב בבית, והיא בודקת רק כשהוא דלוק.

- **מודעה חדשה** שמתאימה לחיפוש מגיעה לטלגרם עם תמונה, פרטים וכפתורים: ⭐ שמור, 🙈 לא רלוונטי.
- **ירידת מחיר** במודעה מתאימה נשלחת כהתראה 📉.
- **אותה דירה בכמה אתרים** מזוהה (לפי רחוב, מספר, חדרים ומחיר), ונשלחת עליה רק התראה אחת.
- **הבדיקה הראשונה** של כל אתר, ובדיקה ראשונה אחרי שינוי בחיפוש, היא "ריצת בסיס": כל המודעות שכבר קיימות נשמרות בשקט, ומגיעה הודעת סיכום אחת.
- **אתר שנכשל 3 פעמים ברצף** (למשל בגלל קפצ'ה) שולח התראה, ואחר כך הודעה נוספת כשהוא חוזר לעבוד.
- **ריהוט וחניה:**
  - לכל מודעה חדשה המערכת קוראת את דף המודעה עוד לפני ההתראה, ושולפת ממנו אם הדירה מרוהטת (כולל "חלקית"), אם יש חניה וכמה, ואת טקסט המודעה.
  - מודעות קיימות מושלמות בהדרגה, עד 4 בכל בדיקה.
  - זה עובד ביד2, בקומו ובהומלס. ב-OnMap יש רק חניה, ובמדלן אין, כי שם לא נפתחים דפי מודעה.
  - בהגדרות אפשר לבחור "מרוהטת בלבד", "לא מרוהטת בלבד" או "רק עם חניה". מודעה שעוד לא ידוע עליה לא נפסלת.
- **שכונות:**
  - בדף **שכונות** בוחרים על המפה את השכונות שבהן מחפשים: לחיצה על שכונה, או ציור מסביב לכמה שכונות. מודעה משכונה אחרת לא נחשבת מתאימה ולא נשלחת עליה התראה.
  - כל מודעה משויכת לאחת מ-40 השכונות הרשמיות של ראשון לציון:
    - ביד2, במדלן וב-OnMap לפי הנקודה של המודעה על המפה.
    - בקומו ובהומלס לפי שם השכונה שבמודעה, גם כשהוא כתוב אחרת ("רמבם", "קרית", "נוה").
  - שם כללי מדי ("מרכז", "המזרח") לא משויך לשום שכונה, וגם מודעה בלי שכונה ובלי נקודה. מודעות כאלה עוברות את הסינון, אלא אם מכבים את זה בדף השכונות.
  - בכרטיס המודעה ובטלגרם מופיע "(לפי המפה: ...)" כשהשכונה לפי המפה שונה ממה שכתוב במודעה.
  - גבולות השכונות לקוחים ממערכת ה-GIS של עיריית ראשון לציון (שכבת "גבול שכונה"), והמפה מ-OpenStreetMap.

## התקנה

צריך רק [Docker Desktop](https://www.docker.com/products/docker-desktop/). Python, Chrome וכל השאר נמצאים בתוך הקונטיינר.

1. יוצרים בוט טלגרם: בטלגרם פותחים את ‎@BotFather ושולחים `/newbot`.
   - מומלץ גם לשלוח `/setjoingroups`, לבחור את הבוט ולבחור **Disable**, כדי שאף אחד לא יוכל להוסיף אותו לקבוצה.
2. מעתיקים את `.env.example` לקובץ `.env`, ומדביקים את ה-token בשורה `TELEGRAM_BOT_TOKEN=`. הקובץ `.env` לא נכנס ל-git.
3. מפעילים:
   ```powershell
   docker compose up -d --build
   ```
4. יוצרים את המשתמש הראשון (מנהל). הפקודה מדפיסה קישור הרשמה חד-פעמי; פותחים אותו ובוחרים שם משתמש וסיסמה:
   ```powershell
   docker compose exec app python -m roomfinder invite --admin
   ```
5. בדשבורד (http://localhost:8000), בדף **החשבון שלי**, לוחצים **➕ חבר טלגרם**, פותחים את הקישור (או סורקים את הקוד) ולוחצים Start בטלגרם.

## משתמשים והרשאות

- **בלי התחברות לא רואים כלום ולא עושים כלום.** כל כתובת בדשבורד, כולל כתובות שלא קיימות, מפנה לדף הכניסה. פתוחים רק דפי הכניסה, ההרשמה והאיפוס, וקובצי העיצוב.
- **אין הרשמה פתוחה.** חשבון נפתח רק מקישור הזמנה שמנהל יוצר בדף **משתמשים**. כל קישור חד-פעמי ותקף ל-3 ימים, ואפשר לבטל אותו לפני שנוצל.
- **תפקידים:**
  - מנהל: הכול, כולל ניהול משתמשים והדפדפן של המערכת.
  - משתמש: מודעות, מקורות, הגדרות והטלגרם שלו.
  - הסימונים (מועדפים, "לא רלוונטי", הערות) משותפים לכולם.
- **שכחת סיסמה?** מנהל יוצר קישור לאיפוס מדף המשתמשים. תקף ל-24 שעות ולשימוש אחד.
- **אם שכחת את הסיסמה של המנהל היחיד:**
  ```powershell
  docker compose exec app python -m roomfinder reset-link <username>
  ```
- **ניתוק והשבתה:** משתמש שמושבת או נמחק מתנתק מיד מכל המכשירים ומפסיק לקבל התראות בטלגרם. מדף **החשבון שלי** אפשר לנתק את כל המכשירים האחרים.
- **טלגרם:** הבוט עונה רק למי שחיבר טלגרם לחשבון פעיל, דרך קישור חד-פעמי (תקף ל-10 דקות) מדף החשבון. כל אחד אחר לא מקבל ממנו שום תשובה.
- **מה עוד מוגן:**
  - סיסמאות נשמרות רק כ-hash מסוג Argon2.
  - עוגיית ההתחברות מסומנת HttpOnly ו-SameSite.
  - אחרי 5 ניסיונות כושלים הכניסה ננעלת ל-15 דקות.
  - בקשות מאתרים אחרים נחסמות.
  - אין דף תיעוד API פתוח.
  - `/health` עונה רק מתוך הקונטיינר.
  - בייצוא ה-CSV, נוסחאות שמגיעות מטקסט של מודעות מנוטרלות.

רשימת המשתמשים משורת הפקודה: `docker compose exec app python -m roomfinder users`.

כדי שהמעקב ירוץ תמיד, מומלץ להפעיל ב-Docker Desktop את **Start Docker Desktop when you sign in**, ולוודא שהמחשב לא נכנס למצב שינה. הקונטיינר עולה מחדש מעצמו (`restart: unless-stopped`).

## שימוש יומיומי

- **דשבורד** (http://localhost:8000):
  - **מודעות:** חדשות / הכול / מועדפים / יצרתי קשר / לא רלוונטי / הוסרו, עם סינון לפי אתר, שכונה (לפי המפה) ומחיר, והערות אישיות לכל דירה.
  - **מקורות:** המצב של כל אתר, בדיקה ידנית ("בדוק עכשיו"), כיבוי והדלקה, תדירות, וכתובת חיפוש מותאמת.
  - **שכונות:** בחירת השכונות על מפה, עם מספר המודעות המתאימות בכל שכונה.
  - **הגדרות:** מה מחפשים, שעות שקטות (ההודעות מגיעות בלי צליל), שעות לילה (בדיקות פחות תכופות), וייצוא ל-CSV.
  - **החשבון שלי:** טלגרם, החלפת סיסמה וניתוק מכשירים.
  - כשהדשבורד פתוח, מודעה חדשה מקפיצה גם התראת דפדפן עם צליל.
- **פקודות בטלגרם:** `/status`, `/latest`, `/pause`, `/resume`.
- **הדפדפן של המערכת** (למנהלים, בדף **מקורות**): אם אתר מציג בדיקת "אני לא רובוט", אפשר לפתוח את הדפדפן בתוך הדשבורד, לפתור אותה בעצמך, ואז ללחוץ "בדוק עכשיו". אין לו פורט נפרד, והוא זמין רק אחרי כניסה כמנהל.

### הערה על מדלן
מדלן מוגן במערכת PerimeterX, שחוסמת דפדפנים שנראים לה אוטומטיים ומציגה בדיקת "לחץ והחזק". לכן מדלן נבדק רק פעם בשעה, עם הפסקות ארוכות בין עמודים. אם הוא נחסם שוב ושוב, אפשר לפתור את הבדיקה ידנית בדפדפן של המערכת, או לכבות אותו בדף המקורות. רוב המודעות שבו מופיעות גם ביד2.

## תחזוקה

```powershell
docker compose logs -f app            # לוגים
docker compose restart app            # הפעלה מחדש
docker compose up -d --build          # אחרי עדכון קוד
```

הנתונים נשמרים ב-volume בשם `roomfinder_roomfinder-data`: מסד הנתונים (מודעות, סימונים, הערות, הגדרות, משתמשים וחיבורי טלגרם) ופרופיל הדפדפן. הם נשארים גם כשהקונטיינר נבנה מחדש, ב-`docker compose down` וב-`up -d --build`.

`docker compose down -v` **מוחק את ה-volume**, ואחריו המערכת מתחילה מאפס:
- כל המשתמשים נמחקים. יוצרים מנהל חדש עם `invite --admin`, כמו בהתקנה.
- צריך לחבר מחדש את הטלגרם מדף החשבון. ה-token נשאר, כי הוא ב-`.env`.
- צריך להגדיר מחדש את החיפוש וההעדפות.
- הבדיקה הראשונה של כל אתר תהיה שוב ריצת בסיס.

גיבוי ושחזור (מתיקיית הפרויקט):
```powershell
# גיבוי לקובץ roomfinder-backup.tgz (עוצרים לרגע, כדי שמסד הנתונים לא ישתנה באמצע)
docker compose stop
docker run --rm -v roomfinder_roomfinder-data:/data -v ${PWD}:/backup alpine tar czf /backup/roomfinder-backup.tgz /data
docker compose start
# שחזור: קודם docker compose down, אחר כך
docker run --rm -v roomfinder_roomfinder-data:/data -v ${PWD}:/backup alpine sh -c "rm -rf /data/* && tar xzf /backup/roomfinder-backup.tgz -C /"
docker compose up -d
```

## פיתוח

הכול רץ בתוך Docker:

```powershell
# הרצה עם הקוד מהתיקייה וטעינה מחדש אוטומטית (בלי מתזמן)
docker compose -f compose.yaml -f compose.dev.yaml up -d --build

# בדיקות ו-lint
docker compose exec app pytest
docker compose exec app ruff check .

# בדיקה ידנית של אתר: רק מדפיס, בלי לשמור ובלי לשלוח
docker compose exec app python -m roomfinder fetch yad2
# בדיקה מלאה של אתר: שמירה והתראות
docker compose exec app python -m roomfinder run yad2
# הודעת בדיקה לטלגרם
docker compose exec app python -m roomfinder notify-test
```

מבנה עיקרי:
- `src/roomfinder/sources/`: מקור לכל אתר. כל מקור מחזיר רשימת `ListingData`.
- `pipeline.py`: שמירה, זיהוי חדשות, ריצת בסיס, ירידות מחיר ומודעות שהוסרו.
- `dedupe.py`: זיהוי אותה דירה בכמה אתרים.
- `areas.py` ו-`data/areas/`: מפת השכונות, ושיוך מודעה לשכונה (לפי נקודה או לפי שם).
- `runner.py`: בדיקה אחת של מקור, כולל התראות וטיפול בכשלונות.
- `scheduler.py`: תזמון עם השהיה אקראית, מצב לילה ו-backoff.
- `notify/telegram.py`: הבוט.
- `auth.py`: חשבונות, סיסמאות, התחברויות וקישורים חד-פעמיים.
- `web/`: הדשבורד (FastAPI, Jinja2, HTMX, Bootstrap RTL):
  - `security.py` ו-`main.py`: שער ההתחברות.
  - `accounts.py`: כניסה, הרשמה וניהול משתמשים.
  - `novnc.py`: הדפדפן של המערכת למנהלים.
  - `static/areas.js`: המפה של דף השכונות (Leaflet).
